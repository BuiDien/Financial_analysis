# v2 Refactor Plan — system + UI/UX

Branch: `refactor/v2`. DB backup: `Financial_analyze/backend/helix.db.bak-20261124-before-v2-refactor`.
Rules for every task: never `git commit`/`git push` (user commits). Never write to the real
`backend/helix.db` from tests or scripts. Backend gate: `cd Financial_analyze/backend && .venv/bin/python -m pytest -q`
must stay green (baseline: 975 passed, 1 skipped). Fully local at runtime (no CDN, no cloud).
vnstock stays pinned at 4.0.4.

Two tracks run in parallel; they touch disjoint directories.

## Track A — backend (`Financial_analyze/backend/`), sequential

### A1. Thin routes → domain services
- `routes/ocr_inbox.py` (1356), `routes/sync.py` (1194), `routes/portfolio.py` (910): move
  business logic, serialization helpers and DB queries into `app/services/` (or a domain package
  `app/ocr/`, `app/portfolio/`, `app/sync/` — pick one convention, follow `screener/` / `newswatch/`).
- Route functions become: validate input → call service → return. HTTP paths, request/response
  shapes and status codes MUST NOT change (frontend + OCR worker + MCP depend on them).
- Tests that monkeypatch moved symbols: update import paths; do not weaken assertions.

### A2. Unified job runner
- New `app/jobs/` module: a `jobs` table (id, kind, status queued/running/done/failed/cancelled,
  progress, message, payload json, result json, error, created/started/finished_at), a
  `JobRunner` with a small thread pool, `submit(kind, payload)`, `register(kind, fn)`, progress
  callback, cancellation flag, and `recover()` on startup (running → failed/requeued per kind).
- Migrate ad-hoc threads onto it: `routes/portfolio.py` thread, `services/ssi_import.py` thread.
  Periodic loops (screener refresh, gmail poller) get registered as *scheduled* jobs in one
  `Scheduler` (interval loop, start/stop in lifespan) so lifespan has one start/stop call.
  Keep existing domain job tables if the UI reads them; the runner may wrap them.
- Add `GET /api/jobs?status=&kind=&limit=` and `GET /api/jobs/{id}` (read-only) for an Activity view.
- `sync.py` asyncio tasks (OCR worker socket) stay asyncio — do not force into threads.

### A3. Market data provider seam
- One `app/marketdata/` package: `MarketDataProvider` protocol (quotes, ohlcv history,
  fundamentals/ratios, listings) + `VnstockProvider` + `YFinanceProvider` (gold/US) + a TTL cache.
- `services/market.py`, `services/fundamentals.py`, `backtest/data.py`, `services/portfolio_engine.py`
  and the screener provider go through it; nothing outside `app/marketdata/` imports vnstock/yfinance
  directly (screener's existing provider may become a thin adapter over it).
- Goal: swapping to a broker API = one new adapter (vnstock sunset).

### A4. Alembic migrations
- Add `alembic` to requirements (it is a dev+runtime dep; install into `.venv`).
- `backend/alembic/` + `alembic.ini`; baseline revision = current full schema.
- Startup (`init_db`): if DB has no `alembic_version` but has tables → run existing legacy
  `_upgrade_*` functions, `create_all` for missing tables, then `stamp head`; else `upgrade head`.
  Fresh DB → `upgrade head`. Remove ad-hoc ALTERs from `db.py` after they live in the legacy path.
- Test against a COPY of the backup DB in a tmp dir to prove upgrade works on real data.

### A5. Alerts to backend + cleanup
- Alerts live in browser `localStorage` (`helix_alerts_v1`). Add `alerts` table + CRUD
  `GET/POST/PATCH/DELETE /api/alerts` (+ `POST /api/alerts/import` to migrate a localStorage dump).
- Cleanup: repo-root `news_collector.py`, `news_data.json` (dupes of `services/news_collector.py`) →
  delete if unreferenced; `Financial_analyze/news.doc` → move to `docs/archive/`.
  Do not move `.venv` folders (not relocatable). Do not touch `spikes/`.

## Track B — frontend (`Financial_analyze/` html, `src/`, `tweaks-panel.jsx`, `scripts/run.sh`), sequential

### B1. Vite migration (mechanical, no visual change)
- `Financial_analyze/web/` (or root-level `package.json` in `Financial_analyze/`) with Vite + React 18.3.1
  (same version as vendored). Convert each `src/*.jsx` to an ES module: explicit `import`/`export`
  instead of `window.*` globals and implicit shared top-level names. Keep `window.HelixAPI`,
  `window.toast`, `window.askPrompt` only if something outside the bundle needs them.
- Inline `<style>` in `Financial Analyze.html` → `src/styles/*.css`. Self-host fonts from `vendor/fonts`.
  lightweight-charts via npm (`lightweight-charts@4.2.3`).
- Build to `Financial_analyze/dist/`; `scripts/run.sh` serves `dist/` (python http.server is fine) and
  rebuilds if sources are newer; `npm run dev` with Vite on :5500 for development.
  Remove `HELIX_BUILD` cache-bust and `babel.min.js` usage.
- Verify: `npm run build` clean, app boots, every page renders with backend live.

### B2. Information architecture + routing + data layer
- Hash routing: `#/today`, `#/scan`, `#/scan/backtest`, `#/company/:ticker/:tab`, `#/portfolio`,
  `#/inbox/:tab`, `#/settings`. Back/forward + deep links work. Old page ids redirect.
- New nav (6 items):
  - **Today** = Home + Dashboard merged (market pulse VN-first: VNINDEX/VN30/HNX, holdings snapshot,
    triggered alerts, news hits).
  - **Scan** = Screener + Backtest tab.
  - **Company** = Asset Detail + Financial Statements + filings + notes, tabbed per ticker.
  - **Portfolio**.
  - **Inbox** = OCR Inbox + Sync + Gmail import as tabs + Jobs/Activity tab (`/api/jobs`).
  - **Alerts & News** may live under Today (panels) with full views reachable at `#/today/news`, `#/today/alerts`.
  - **Settings**.
- Remove US mock data (`#market-data` JSON block, demo mode) and hardcoded sidebar watchlists
  ("AI & Semis", …): sidebar reads `WatchlistStore`.
- Shared data layer: one `useQuery(key, fetcher, {refreshMs})` hook with in-memory cache, dedupe and
  focus-refetch, replacing per-page `setInterval` pollers. Alerts use `/api/alerts` (one-time import of
  localStorage alerts).
