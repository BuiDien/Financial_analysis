# Backtest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pick a built-in strategy, a ticker (VN or US), and a date range. Replay daily history to see how the strategy would have done against buy-and-hold: metrics, an equity curve, and trades marked on the price chart.

**Architecture:** There is a new pure-Python package `backend/app/backtest/` with indicators, a strategy registry, an engine and metrics. None of it does I/O except `data.py`. It sits behind two FastAPI endpoints (`GET /api/backtest/strategies`, `POST /api/backtest/run`). A new frontend page `src/page-backtest.jsx` reuses `LWChart`, which gets a small optional `lines` overlay prop for the equity-vs-benchmark chart. Nothing is persisted (v1 is stateless; every run is recomputed).

**Tech Stack:** FastAPI, pydantic, vnstock 4.0.4 (VCI) through the existing `market._vn_history`, yfinance, React 18 UMD + Babel standalone, Lightweight Charts 4.2.3.

**Spec:** There is no separate spec. The user skipped the questions and asked for a plan to be built overnight ("build the strategies for me, then run them over old data and see how well they do"). The design decisions are in this header and are the planner's calls.

**Interfaces:**
- Produces (all return `list[float | None]`, same length as input, `None` until enough data):
  - `sma(values: list[float], n: int)`: simple mean of the last n values, including index i.
  - `ema(values: list[float], n: int)`: seeded with the SMA of the first n, then `k = 2/(n+1)`.

  - `highest(values: list[float], n: int)` / `lowest(values, n)`: max/min of the n values **before** index i (exclude i). First value at index n. Breakout needs "prior n-day high".

### Task 2: Strategy registry

**Files:**
- Create: `backend/app/backtest/strategies.py`
- Test: `backend/tests/test_backtest_strategies.py`

**Interfaces:**
- Consumes: Task 1 indicators.
- Produces:
  - `@dataclass(frozen=True) class ParamSpec: key: str; label: str; default: float; min: float; max: float; step: float = 1`
  - `@dataclass(frozen=True) class Strategy: id: str; name: str; description: str; params: tuple[ParamSpec, ...]; targets: Callable[[list[dict], dict], list[int]]`
  - `list_strategies() -> list[dict]`: JSON-ready: `[{"id","name","description","params":[{"key","label","default","min","max","step"}]}]`, in registry order.
  - `get_strategy(strategy_id: str) -> Strategy`: raises `KeyError` if unknown.
  - `resolve_params(strategy: Strategy, params: dict | None) -> dict[str, float]`: fills defaults. Raises `ValueError` with a readable message for an unknown key or a value outside `[min, max]`. Integer-valued specs (all of them in v1) are returned as `int`.
  - The `targets(bars, params)` result is `list[int]` with the same length as bars. `1` means "be long after this bar's close", `0` means "be flat". A `None` indicator always gives `0` for entries; for exits it keeps the previous state.

Registry (exact ids, names, params and rules):

| id | name | params (default, min, max) | rule |
|---|---|---|---|
| `buy_hold` | Buy & hold | none | always 1 |
| `sma_cross` | Moving-average crossover | `fast` (20, 2, 200), `slow` (50, 5, 400) | 1 while `sma(fast) > sma(slow)`. `resolve_params` raises if `fast >= slow`. |
| `rsi_reversion` | RSI mean reversion | `period` (14, 2, 50), `buy_below` (30, 5, 50), `sell_above` (70, 50, 95) | stateful: enter when `rsi < buy_below`, exit when `rsi > sell_above`, otherwise hold the previous state |
| `breakout` | Breakout (Donchian) | `entry` (20, 5, 200), `exit` (10, 2, 200) | stateful: enter when `close > highest(high, entry)`, exit when `close < lowest(low, exit)` |

Descriptions: one plain-English sentence each, shown in the UI (e.g. "Buy when the 20-day average crosses above the 50-day; sell when it crosses back below.", with numbers referring to the defaults).

### Task 3: Engine

**Files:**
- Create: `backend/app/backtest/engine.py`
- Test: `backend/tests/test_backtest_engine.py`

**Interfaces:**
- Consumes: bars and a `targets: list[int]` (Task 2 shape).
- Produces: `run_backtest(bars: list[dict], targets: list[int], *, initial_capital: float, fee_rate: float, sell_tax_rate: float, lot_size: int, price_scale: float, min_hold_bars: int, start_index: int = 0) -> dict` returning:
  - `"equity"`: `[{"date": str, "value": float}]`, one per bar from `start_index` to the end, valued at `cash + shares * close * price_scale`.
  - `"trades"`: `[{"entry_date", "entry_price", "exit_date", "exit_price", "shares", "pnl", "return_pct", "bars_held", "open"}]`. Prices are in bar units (not scaled). `pnl` is in currency, net of fees and tax. `return_pct = pnl / entry_cost * 100`, where `entry_cost` includes the buy fee. An open trade has `exit_date=None`, `exit_price=None`, `open=True`, and pnl and return marked to the last close **minus** the would-be sell fee and tax.
  - `"exposure_bars"`: int, the number of bars in `[start_index, end]` that closed holding shares.

Rules:
- `rate` arguments are fractions (0.0015, not 0.15).
- Only `targets[i]` for `i >= start_index` act. Bars before `start_index` exist only for indicator warm-up.
- When `targets[i]` differs from the current position, fill at `bars[i+1]["open"]` (no fill when i is the last bar).
- Buy: `shares = floor(cash / (open*scale*(1+fee)) / lot) * lot`. If `shares == 0`, skip; the target is re-checked on later bars. `cash -= shares*open*scale*(1+fee)`.
- Sell: allowed only when `fill_index - entry_index >= min_hold_bars`. Otherwise the sell is pending and re-evaluated each bar while the target stays 0. A pending sell is cancelled if the target returns to 1. `cash += shares*open*scale*(1 - fee - tax)`.

    strategy: str
    params: dict[str, float] = {}
    start: date
    end: date

Orchestration: `load_daily_bars(ticker, start - WARMUP_DAYS, end)` → `start_index` = first bar with date ≥ start → `resolve_params` → `targets` → `run_backtest` → `compute_metrics`. Then repeat with `buy_hold` and the same settings to get the benchmark.

Errors, all `HTTPException` with a readable `detail`: unknown strategy → 400; `ValueError` from `resolve_params` → 400; `start >= end` → 400; fewer than 2 bars at or after start → 400 "Not enough price history in this range"; `ValueError` from the loader → 404 "No price data for {ticker}"; `VnRateLimited` → 503 "VN data provider rate-limited, try again in a minute"; any other loader exception → 502.
